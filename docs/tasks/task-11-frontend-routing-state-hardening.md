## 1. Detailed Scope & Feature Coverage

### 1.1 Problem Statement

The frontend has the right libraries but incomplete ownership boundaries:

1. `App.tsx` implements routing through `window.history.pushState`, `popstate`, and a default-to-deliveries branch. Unknown paths silently render deliveries, `/` renders deliveries without a canonical redirect, and route names are untyped.
2. One process-wide `QueryClient` remains mounted while the Zustand JWT session changes. Logging out, expiring, receiving HTTP 401, or logging in as another user does not cancel requests and clear cached server data.
3. Query keys such as `['deliveries']` and `['contracts']` omit list parameters. Pagination, filtering, or sorting would alias different server results into the same cache entry.
4. Mutation hooks retry every non-`ApiError`, including network failures for non-idempotent `POST` creates. A committed request with a lost response can be executed more than once.
5. SignalR subscribes to every aggregate group, while React cache synchronization only patches or invalidates physical deliveries. Contracts, market prices, dashboards, and analytics may remain stale after remote writes.
6. CRUD conflicts generally roll back and reconcile, but dashboard HTTP 409 handling only asks the user to reload; it neither installs/refetches current server state nor shows the standard conflict prompt.
7. The command palette opens the delivery modal with `window.dispatchEvent(new CustomEvent(...))`, an untyped global event bus with no lifecycle or session reset.

### 1.2 Required Outcomes

- `@tanstack/react-router` is the sole owner of browser URL, history, route matching, protected-route redirects, lazy route loading, not-found behavior, and navigation APIs.
- TanStack Query remains the sole owner of server-derived data. Its cache is isolated between authentication sessions and synchronized with successful mutations, conflicts, and realtime events.
- Zustand owns only shared, ephemeral client state: the in-memory authentication session and cross-tree UI commands/modal state. It must not duplicate Query data or router URL/search state.
- D5 remains intact: optimistic mutation, rollback on failure, server-current HTTP 409 response, refetch/reconciliation, visible conflict prompt, and no silent client-wins path.
- Existing direct imperative operations remain outside Query when appropriate: login submission, SignalR connection/catch-up transport, and the session-scoped undo/redo command stack.

### 1.3 In Scope

- Install one reviewed, exact version of `@tanstack/react-router` plus the matching `@tanstack/router-plugin`, configure the Vite plugin, and commit the lockfile.
- Replace `useBrowserPath`, manual `pushState`, and manual `popstate` listeners with a typed route tree.
- Provide protected routes for deliveries, contracts, market prices, and dashboard; an anonymous login route; a canonical `/` redirect; and an explicit not-found view.
- Preserve dashboard code splitting and defer chart-engine registration until the dashboard route loads.
- Pass `QueryClient` through router context so route preloaders and components share one cache.
- Introduce query-option/key factories with list parameters and entity-detail identifiers.
- Implement centralized session start/end orchestration that cancels in-flight queries and clears Query and shared UI state on login identity change, logout, token expiry, and authenticated HTTP 401.
- Make mutation retry policy explicit and safe.
- Reconcile all 409 flows, including dashboards, with current server state and a visible prompt.
- Map every subscribed SignalR aggregate type to its affected Query key roots; patch only payloads with a verified DTO contract and invalidate the rest.
- Replace the DOM `CustomEvent` palette-to-page bridge with typed navigation plus a small Zustand UI store.
- Add focused Vitest coverage for every boundary above. Task 09 remains the owner of browser-level Playwright coverage.

### 1.4 Out of Scope

- Backend route, DTO, database, or enum changes.
- Persistent authentication in `localStorage`, `sessionStorage`, IndexedDB, or cookies managed by frontend JavaScript.
- Offline writes, Dexie, `/api/v1/mutations/batch`, three-way merge, or background mutation replay.
- Moving server entities, query loading/error flags, route/search parameters, form fields, or undo history into Zustand.
- Introducing XState usage in this task. No implemented multi-step workflow currently requires a state machine, but the existing exact-pinned `xstate` dependency remains an approved frontend capability for future workflow work and must not be removed merely because it has no current call sites.
- Adding idempotency keys to backend mutations. Until such a contract exists, unsafe mutation retries remain disabled.

## 3. Architecture & Code Contract Blueprints

### 3.1 Typed Router Contract

The route tree must expose these observable behaviors:

| Route | Authentication | Behavior |
| :--- | :--- | :--- |
| `/` | Any | Typed redirect to `/deliveries` when authenticated, otherwise `/login` |
| `/login` | Anonymous | Login form; authenticated users redirect to a validated internal return path or `/deliveries` |
| `/deliveries` | Required | Delivery page; optional validated search state controls the create modal |
| `/contracts` | Required | Contract page |
| `/market-prices` | Required | Market-price page |
| `/dashboard` | Required | Lazy dashboard bundle and chart adapter registration |
| unmatched | Any | Explicit not-found UI; never silently render deliveries |

Requirements:

- Router context contains the shared `QueryClient` and read-only session access required by guards/loaders.
- Protected loaders do not start authenticated queries before the guard succeeds.
- Return paths accept only known internal routes; external URLs and protocol-relative values are rejected.
- AppShell links and cmdk actions use typed router navigation. No feature may call History API methods directly.
- The existing backend fallback must continue serving `index.html` for non-`/api` and non-`/hubs` deep links.
- File-based routing is generated through `@tanstack/router-plugin` configured for `src/app/routes`; `routeTree.gen.ts` is committed/generated according to the selected plugin workflow and excluded from manual lint fixes.

Primary references: [TanStack Router file-based routing](https://tanstack.com/router/latest/docs/routing/file-based-routing), [Vite installation](https://tanstack.com/router/v1/docs/installation/with-vite), and [authenticated routes](https://tanstack.com/router/latest/docs/guide/authenticated-routes).

### 3.2 Hierarchical Query Keys

All query keys must be produced by factories, not repeated array literals:

```ts
export const queryKeys = {
  deliveries: {
    all: ['deliveries'] as const,
    lists: () => ['deliveries', 'list'] as const,
    list: (request: DeliveryListRequest) => ['deliveries', 'list', request] as const,
    details: () => ['deliveries', 'detail'] as const,
    detail: (id: string) => ['deliveries', 'detail', id] as const,
  },
  dashboards: {
    all: ['dashboards'] as const,
    detail: (id: string) => ['dashboards', 'detail', id] as const,
  },
  analytics: {
    all: ['analytics'] as const,
    result: (widgetId: string, ast: JsonQueryAst) => ['analytics', widgetId, ast] as const,
  },
} as const;
```

Equivalent factories are required for contracts, market prices, and every domain key exported for later screens. List request objects must contain normalized pagination, sort, and filter values so logically identical requests hash identically.

### 3.3 Session Isolation Contract

Session lifecycle is an application service, not a side effect hidden inside a component:

```text
beginSession(new token)
  -> cancel old authenticated requests
  -> clear old Query cache and shared UI state
  -> install new in-memory auth session
  -> invalidate router guards and navigate to validated return path

endSession(reason: logout | expired | unauthorized)
  -> cancel authenticated requests
  -> clear Query cache and shared UI state
  -> clear in-memory auth session
  -> invalidate router guards and replace history with /login
```

- `apiFetch` routes authenticated HTTP 401 through `endSession('unauthorized')`.
- Token-expiry timers and the sign-out button use the same controller.
- A second login in the same browser process must never render data cached for the first login, including during a background refetch.
- Zustand stores must not import `QueryClient`; the session controller coordinates independently owned systems.

### 3.4 Query and Mutation Policy

- Queries may retry transient network failures using the shared QueryClient policy; HTTP 4xx responses are not retried.
- Mutations default to `retry: false`.
- A mutation may opt into retry only when its endpoint has a documented idempotency key or is proven idempotent under the exact request contract.
- Optimistic mutations snapshot every affected matching list/detail cache, not just one hard-coded list key.
- Success replaces optimistic entities with the authoritative DTO and version.
- Non-409 error restores the complete snapshot and surfaces the failure.
- HTTP 409 restores optimistic state, installs the server-current DTO returned by the endpoint where applicable, invalidates/refetches the affected key, and displays `ConflictDialog` with server state plus attempted edits.
- `WorkspaceDashboard` uses the same conflict contract; “reload manually” alone is not accepted.

### 3.5 Realtime Query Synchronization Contract

Define one exhaustive aggregate mapping adjacent to the event envelope:

```ts
const affectedQueryRoots: Record<KnownAggregateType, readonly QueryKey[]> = {
  PhysicalDelivery: [queryKeys.deliveries.all, queryKeys.analytics.all],
  Contract: [queryKeys.contracts.all, queryKeys.analytics.all],
  MarketPrice: [queryKeys.marketPrices.all, queryKeys.analytics.all],
  WorkspaceDashboard: [queryKeys.dashboards.all],
  // CapacityBooking, Transfer, BioticketDelivery, GooCertificateTransaction,
  // TaxTariff, and Hedge map to their domain roots.
};
```

- Physical-delivery payloads may retain their verified direct patch path.
- Aggregate payloads without a complete DTO contract trigger batched invalidation, not partial-object casting.
- Every group in `dashboardSubscriptionGroups` must have a mapping or an explicit tested ignore reason.
- Existing event batching remains in force so a burst does not issue one refetch per event.

### 3.6 Zustand UI Contract

The UI store is intentionally small:

```ts
type GlobalModal = 'create-delivery' | null;

interface UiState {
  activeModal: GlobalModal;
  openModal: (modal: Exclude<GlobalModal, null>) => void;
  closeModal: () => void;
  reset: () => void;
}
```

- The command palette navigates to `/deliveries` through the router, then opens the typed modal through the UI store.
- `DeliveriesPage` derives modal visibility from the store; the DOM `CustomEvent` and document-level modal listener are deleted.
- If product requirements make the modal shareable or back-button-controlled, its state belongs in validated router search parameters instead of Zustand. The implementation must choose one owner and must not mirror the same state in both.
- Form contents, errors, Query data, mutation states, and route paths remain outside this store.

## 6. Anti-Cheating & Integrity Guardrails

1. Do not retain `useBrowserPath`, manual History API listeners, or a second path state beside TanStack Router.
2. Do not satisfy route tests by mocking the router itself; use memory history with the production route tree.
3. Do not put API responses or Query loading/error state into Zustand.
4. Do not persist JWTs or sensitive session state in browser storage.
5. Do not clear Query cache during ordinary navigation; clear it only at a session identity boundary or an explicitly scoped recovery action.
6. Do not retry mutations merely because the failure is a JavaScript `TypeError`; retries require a documented idempotency guarantee.
7. Do not resolve HTTP 409 by resubmitting with the new version, overwriting server state, or silently choosing client values.
8. Do not cast incomplete realtime payloads into generated DTOs. Patch only verified payload contracts; otherwise invalidate.
9. Do not mirror modal ownership in both router search state and Zustand.
10. Do not edit `src/Frontend/src/api/generated/` by hand.
11. Do not hand-edit `src/Frontend/src/app/routeTree.gen.ts`; fix route files or plugin configuration and regenerate it.
12. Do not remove XState. Retain its exact-pinned dependency for future state-machine-worthy workflows, but do not introduce XState usage, Redux, another router, or another server-cache library in this task.
13. Do not mark the task Implemented until every acceptance command has actually run and its failures can cause a non-zero exit.
